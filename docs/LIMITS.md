# Вход, предел ответа и реальное окно 7.5.5

Входной бюджет не изменён: по умолчанию 56000 токенов. Запрошенное окно — 262144; исходный предел ответа — 196608. В 7.5.5 max_tokens, отправляемый в API, не ниже 110000; более высокое пользовательское значение сохраняется. Это верхний предел, а не требование модели генерировать столько текста.

Предел ответа больше не вычитается целиком при упаковке входа и не делится пополам после ошибок упаковки. Прежняя схема могла сначала уменьшить резерв до нескольких тысяч, а после обрезания снова запускать дорогой запрос. Теперь вход упаковывается в подтверждённое окно отдельно, а max_tokens отправляется серверу как верхний предел.

Физическое ограничение остаётся: системные инструкции, фактический вход и сгенерированный ответ должны помещаться в реально загруженное окно. Принятый сервером max_tokens=196608 не гарантирует 196608 свободных токенов после входа. При окне около 110000 одновременно сохранить вход56000 и выдать ответ110000 невозможно. Настройки загрузки и автоматический отказ по нехватке памяти в этом патче не менялись; квантизация кэша и отключение защиты памяти не включаются.

Если сервер помечает завершённый JSON как length, он проходит прежние обычные проверки решения. Если JSON действительно неполный, действия не применяются и день не пропускается: показывается явная ошибка, автоматическая регенерация того же обрезанного ответа прекращается. Для большего реального ответа нужно большее загруженное окно; большая цифра API не создаёт видеопамять.

stream=true продолжает запрашивать usage и калибровать оценку входа. Бюджет входа, характеры, военный промт, экономика и правила не менялись.

[Параметры загрузки и подтверждённое окно LM Studio](https://lmstudio.ai/docs/developer/rest/load) · [Параметры Chat Completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions).

Байтовая оценка входа консервативна и не является токенизацией модели. Если настроенный бюджет входа с правилами помещается в окно, но оценка оставшегося ядра фактов превышает его, запрос передаётся серверу с сохранением этих фактов: окончательную проверку делает LM Studio. Подтверждённое сервером переполнение в этом случае вызывает явную ошибку без повторения запроса.
